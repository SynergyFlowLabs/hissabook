# Audit 008 — Single-page mobile navigation

Date: 2026-11-10
Branch: `arena/4fca51e5-hissabook`
Request: "Make the mobile app single page. Currently each page takes a lot
of time to load everytime."

## What the complaint actually was

Two independent causes, both real, and fixing only one would have left the
report unfixed:

1. **Every internal link was a raw `<a>`.** 23 of them, across the sidebar,
   mobile menu and all six screens. A raw anchor makes the browser discard the
   document: new HTML, new JS parse, new hydration, new data fetch, and a white
   flash in between. That is a page load, not a navigation.
2. **The shell was mounted *inside* each screen.** `AppSidebar` was rendered by
   `/`, `/transactions`, `/inventory`, `/team`, `/partners` and `/reports`. So
   even after client-side routing, arriving at a screen unmounted and rebuilt
   the sidebar, restarted the notification poll, reset the nav pill animation
   and threw away the open panel.

A third cause showed up only after the first two were fixed, and it is the one
that matches "takes a lot of time" most literally:

3. **Each screen started at `useState(null)` and painted a full-screen loader.**
   Team, Inventory, Partners and Overview blanked the entire page to
   "Preparing your workspace…" on every visit — including a return visit to a
   screen the user had left four seconds earlier. The bytes were already in the
   browser; only the component's memory had been thrown away.

## Fix

- `next/link` everywhere an internal route is navigated. CSV export links stay
  as raw `<a>` on purpose: they must trigger a download, not a transition, and
  that is verified by the guard listing the exact allowed exceptions.
- `components/app-shell.tsx` mounts `AppSidebar` once, in `app/layout.tsx`.
  `current` is derived from `usePathname()` through `currentFromPathname()`, so
  there is one source of truth for the active item instead of a prop per page.
  `/login`, `/setup` and `/invite` render no shell.
- Shell identity comes from `lib/use-workspace-context.ts`: a
  `useSyncExternalStore` module store fed by `/api/workspace/context`, a payload
  of `{userName, workspaceName, businessType, role, loanCount}`. Deliberately not
  `/api/dashboard` — the shell must not pull the ledger on every navigation.
  `/` primes it from the payload it already has, so the sidebar does not issue a
  second request on first paint.
- `lib/route-cache.ts`: a stale-while-revalidate map. Overview, Team, Inventory
  and Partners seed state from it on mount and write back after every fetch
  *and* after every mutation, so a return visit paints instantly and a save can
  never be masked by an older snapshot.

## What this actually saves, measured

Hard document loads on the built app (`next start`, fresh database):

| route | document | RSC payload (a Link tap) | saved |
|---|---:|---:|---:|
| `/` | 29,877 B | 9,731 B | 67% |
| `/transactions` | 48,626 B | 9,994 B | 79% |
| `/inventory` | 30,856 B | 9,987 B | 68% |
| `/team` | 30,631 B | 10,145 B | 67% |
| `/partners` | 30,206 B | 10,151 B | 66% |
| `/reports` | 46,789 B | 9,987 B | 79% |

All six routes are reachable from a nav link that is visible on first paint, so
Next prefetches them: by the time the user taps, the payload is usually already
in the router cache and the tap is a paint, not a fetch. The shell is a shared
dependency — one chunk carries the sidebar and the four route keys together —
so it is not re-sent per route.

## Regressions this change introduced, and how they were caught

This is the part that matters. Hoisting a component out of the pages breaks any
code that silently depended on it being remounted.

1. **The notification bell vanished after one tap.** `TopbarNotifPortal`
   resolved `.topbar-notif-slot` once in `useEffect([])`. That worked only
   because the sidebar remounted with each page. With the shell persistent, the
   slot belongs to the *page*: on navigation the old node is detached and a new
   one is created, so the portal kept pointing at a detached node. This would
   have quietly undone tranche D. Fixed by keying the lookup on `usePathname()`
   and observing for a slot that commits a tick late. Guarded by a test, because
   it is invisible until you navigate twice.
2. **`forgetCache` had no `window` guard.** The new cache is module state inside
   client components that are *also* server-rendered. Without the guard a warm
   Node process would serve one visitor the previous visitor's ledger. The test
   that asserts three guarded functions failed on the first run and caught it.
   Verified afterwards: SSR HTML for `/`, `/team` and `/partners` contains no
   PKR amounts at all.
3. **Both caches outlived the session.** Signing out and back in as someone else
   on the same device would paint the previous account's totals and loan badge
   for one frame. Both sign-out paths now clear the payload cache and reset the
   identity store.

## Deliberately not done

- **A true single route that swaps panels.** The App Router already gives client
  transitions and per-route payload splitting once links are `Link`. Collapsing
  six routes into one component would have cost URL addressability, deep links,
  the browser back button and per-screen code splitting to save bytes that are
  already saved.
- **Seeding the shell from the layout.** Tempting, since `/` is dynamic. But it
  means running the dashboard query in the root layout for every route,
  including the public landing page. The floating sidebar is `display: none`
  under 901px anyway, and the mobile pill shows neither name nor badge, so the
  placeholder-then-real swap is invisible on the device the report came from.
- **Removing the per-page `className="app-shell"` wrappers.** They are the
  scroll targets for `/#overview`, `/#accounts` and `/#loans`. Left alone.
- **Touching `html { scroll-behavior: smooth }`.** It looked like a trap for
  Next's scroll reset, but `layout-router` sets `htmlElement.scrollTop = 0`
  directly, which ignores `scroll-behavior`. It is still needed for the
  `/#accounts` hash links. Verified in the installed Next source rather than
  assumed.

## Verification

- `tsc --noEmit` clean at every step.
- **94/94** tests (85 before this tranche, 9 added): no raw internal anchor;
  shell mounted once and only by the layout; `current` derived from the pathname;
  notification slot re-resolved per route; server scope keeps per-visitor
  payloads out; screens seed from the cache; sign-out clears both caches; full page loads
  survive only on auth surfaces and CSV downloads.
- `npm run build` compiles; `/api/workspace/context` registered.
- Fresh database, `next start`: setup 201, login 302, six screens 200.
  `/api/workspace/context` returns `{userName:"Bilal", workspaceName:"Safa
  Studio", businessType:"Creative agency", role:"OWNER", loanCount:2}`.
- Exactly **one** `<aside class="sidebar">` on every authed screen and **zero**
  on `/login` and `/setup` — the shell cannot double-render.
- Each page carries the same 8 nav links and one brand link, i.e. one shared
  shell rather than a rebuilt one.

## Honest limits

This sandbox has no browser and cannot feel a tap. The speed claim rests on what
changed — no document reload, a ~10 KB payload instead of a 30–49 KB one, no
full-screen loader on return, and a shell that is no longer rebuilt — not on a
timed run on a real phone. The user's own phone check is the acceptance
evidence.
