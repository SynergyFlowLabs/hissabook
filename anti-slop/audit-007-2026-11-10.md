# Anti-slop Audit 007: notification bell moves to the mobile topbar (2026-11-10)

Scope: one instruction. "Move the notifications icon from mobile bottombar to
topbar on the right side of the search icon." Files: `app/globals.css`,
`components/app-sidebar.tsx`, `components/notification-button.tsx`,
`components/topbar-notif-portal.tsx` (new), the six screen topbars,
`lib/anti-slop/mobile-overview.test.ts`, `docs/FEATURES.md`.

Rules: same installed set as Audits 001 to 006. Mode: **during**.

## Why a portal, and not lifted state

Notification state lives in `AppSidebar`: `useNotifications` owns the polling
loop, `notifOpen` owns the panel. The topbar, however, belongs to each of six
screens (`dashboard`, `transactions`, `inventory`, `team`, `partners`,
`reports`). The obvious implementation is to lift that state into every page and
pass four props down each one. That would have meant six copies of the same
wiring, six chances to drift, and six polling loops' worth of mistakes waiting to
happen.

Instead each topbar renders an empty `<span className="topbar-notif-slot" />`
next to its search control, and `TopbarNotifPortal` portals the bell into it. One
owner, one panel, one loop; the control still appears exactly where it was asked
for. A screen that forgot its slot would silently lose the bell, so the test
suite asserts the slot exists in all six files.

If no slot is found the portal renders nothing rather than throwing. The bell
would then be missing on that screen, which is why that case is a test, not a
runtime fallback.

## What was run, and what was only inspected

- `tsc --noEmit`: clean.
- `npm test`: **85/85**, up from 82 (three new guards: portal plus slot on all
  six screens, bell absent from the pill with exactly one portal and one panel,
  and the topbar bell's sizing and desktop hiding).

- Fresh SQLite DB, `next start` on 3100, demo login, all six screens 200.
- Server HTML: the slot appears in `/transactions` and `/reports` (server
  rendered) and not in the four client-rendered screens, which is the expected
  hydration split. Confirmed instead in the client bundles: `topbar-notif-slot`
  in 7 chunks, `notif-topbar-trigger` and `notif-topbar-btn` each present, and
  the served CSS carries the 44px coarse-pointer rule, the 901px hide and the
  recoloured badge ring.
- **Not run**: a browser pass. I cannot tap the bell, so "the panel opens from
  the topbar" rests on it being the same handler and the same panel, plus the
  bundle checks. That is the owner's check.
